# 1. mockup 저장소가 자체 ADR을 관리한다

Date: 2026-08-02
Author: @pkdee

## Status

Accepted

## Context

server ADR-0001(저장소별 ADR 관리)이 ADR을 저장소별로 두기로 정했고, client도 ADR-0001로 같은 구조를 도입했다. mockup만 `doc/` 디렉터리 자체가 없었다.

mockup은 공모전 제출물이 아니라 Flutter 구현의 화면 설계 레퍼런스다. 그래서 "결정을 기록할 만큼 중요한 저장소가 아니다"라고 암묵적으로 취급돼 왔다. 그러나 실제로는 되돌리기 어려운 결정이 이미 쌓여 있다.

1. **당근 SEED 전용화.** 자체 `tokens.css`를 버리고 `@seed-design/css` 하나만 쓰기로 한 결정이 `DESIGN.md` 서술로만 남아 있다. 대안 비교가 사라졌다.
2. **화면 정본이 `bundle.tsx` 단일 파일이다.** 생성 원본을 제거하고 이 파일을 직접 고치기로 한 결정도 기록이 없다.
3. **명세보다 앞선 화면 확장.** 도감 4단 계층(전국 → 광역 → 시군피커 → 시군상세)은 `docs/01-기능명세서`에 없는 신규 확장인데, 왜 그렇게 갈랐는지가 어디에도 없다.

client가 이 저장소를 이식 원본으로 삼는다. 이식하는 사람이 "왜 이렇게 돼 있나"를 물었을 때 답할 문서가 필요하다.

## Decision

**mockup 고유 결정을 `mockup/doc/adr/`에 기록한다.** 이 문서가 그 첫 번째다.

- 형식은 server · client와 동일하게 adr-tools 규약을 따른다. 섹션 헤더는 영문 고정이다.
- `Date:` 아래에 `Author: @핸들`을 적는다. `doc/adr/templates/template.md`가 빈 줄을 만들어 준다.
- 저장소 간 참조는 링크 대신 저장소명 + 번호 + 요지로 적는다. 멀티레포라 상대 경로가 깨진다.
- 소급 작성은 하지 않는다. 위 Context의 과거 결정 3건은 `DESIGN.md`·`AGENTS.md` 서술로 두고, 앞으로의 결정부터 ADR로 남긴다. 마감이 있는 상황에서 과거 재구성에 시간을 쓰지 않는다.

### 결정이 번복되면 새 번호를 따지 않고 그 문서를 고쳐 쓴다 (2026-08-07 추가)

**뒤집힌 결정은 새 ADR로 넘기지 않는다.** 그 ADR의 제목·파일명·본문을 현행으로 고쳐 쓰고, 무엇이 왜 바뀌었는지는 맨 아래 `변경 이력` 절에 남긴다. 번호는 그대로 둔다.

**규칙 정본은 docs `협업규칙.md`의 ADR 절이다.** 근거와 예외(독립적인 새 결정이 옛 결정의 일부만 좁히는 경우)는 거기 있고 여기 옮겨 적지 않는다 - 이 문서가 규칙을 복제하면 세 저장소가 또 갈라진다.

이 규칙이 없어서 실제로 갈라진 적이 있다. **mockup ADR-0002가 자기 본문에 "정식으로 supersede할 새 ADR 작성이 남아 있다"고 적어 둔 채, 정작 값 정정은 그 문서를 고쳐 쓰는 방식으로 처리돼 있었다**(2026-08-07 정리). 규칙이 있었으면 그 문장이 애초에 없었을 자리다.

## Consequences

쉬워지는 것.

- 이식하는 사람이 mockup을 단독으로 읽고 설계 의도를 알 수 있다.
- 세 저장소의 기록 방식이 같아져서 오가며 읽을 때 형식을 다시 익힐 필요가 없다.

어려워지는 것과 리스크.

- 관리할 저장소가 하나 늘었다. `Amends` 표기와 상호 링크를 손으로 관리해야 한다(경로 공백 때문에 `adr new`만 동작한다).
- **과거 결정 3건이 ADR 없이 남는다.** 지금은 `DESIGN.md`가 그 역할을 하지만, 나중에 그 서술이 낡으면 근거를 찾을 곳이 없어진다.
- mockup이 제출물이 아니므로 ADR 작성이 뒤로 밀릴 유인이 있다. 실제로 밀리면 이 결정은 형식만 남는다.

## Alternatives

| 대안 | 기각 사유 |
|---|---|
| ADR을 두지 않고 `DESIGN.md`에만 적는다 | 지금까지의 방식이고, 그래서 결정 3건의 대안 비교가 사라졌다. 서술 문서는 "무엇을 골랐나"는 남기지만 "무엇을 왜 버렸나"를 남기지 않는다 |
| client ADR에 mockup 결정까지 함께 적는다 | mockup은 독립 저장소다. client를 클론하지 않으면 못 읽는다. 저장소별 독립 운영 원칙과도 어긋난다 |
| docs 저장소에 모아 둔다 | server ADR-0001이 이미 기각했다. docs는 ADR을 보관하지 않는다 |
| 과거 결정 3건을 소급 작성한다 | 당시 검토한 대안을 지금 재구성하면 사후 합리화가 된다. 1차 제출 마감이 7주 남은 시점에 쓸 시간도 아니다 |
