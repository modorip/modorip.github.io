# 2. 브랜드색과 색 팔레트를 확정한다

Date: 2026-08-02
Author: @pkdee

## Status

Accepted

## Context

브랜드 토큰이 당근 SEED 기본값인 carrot 주황 `#FF6600` 그대로였다. 셋이 걸렸다.

1. **접근성 미달.** 흰 배경 대비 2.94:1로 WCAG AA 본문 기준 4.5:1에 못 미쳤다. `fg.brand`가 링크·아이콘 색으로 쓰이므로 실사용에서 읽히지 않는 자리가 생긴다.
2. **지역색과 구분되지 않았다.** 17광역 충북 tone `#FF5E00`과 색차 ΔE 4로 육안 구분이 불가능했다. 도감 화면에서 브랜드색과 지역 식별색이 같은 색으로 보였다.
3. **당근 시그니처다.** 제휴·후원 관계로 오인시키지 않는다는 원칙과 부딪혔다.

밝은 파랑으로 옮기려 하자 파랑대를 17광역 tone 6개(서울·경기·인천·부산·울산·경남)가 점유하고 있었다. 그 6개만 옮기고 나머지 11개의 흰 글자 대비를 4.5:1로 올리려 명도를 낮추자, 주황대에 몰려 있던 5개가 한 점으로 뭉쳤다(충북 `#CD4B00` ↔ 전북 `#CC4B00`, ΔE 0.4). 부분 보정이 성립하지 않았다.

원인은 색 체계 자체였다. 17광역 + 4계열 = 21개의 진한 색이 색상환을 이미 덮고 있었고, 그것들끼리도 5쌍이 충돌했다(서울↔경기 11.8, 인천↔울산 14.2, 대구↔대전 16.8, 세종↔강원 18.4, 충북↔전북 18.6). 브랜드색이 들어갈 자리가 없었던 것이 아니라, 애초에 21색이 서로 구분되지 않는 상태였다.

## Decision

**브랜드색을 밝은 파랑으로 확정하고, 17광역 식별색과 4계열 색을 전면 재배치한다.**

### 1. 브랜드는 바탕과 글자를 나눈다

구 체계는 `bg.brand-solid`와 `fg.brand`가 둘 다 carrot-600 하나였다. 그래서 "본문 4.5:1"이라는 가장 빡빡한 기준이 버튼 색까지 끌어내려 밝은 색을 쓸 수 없었다. **이 ADR의 핵심은 특정 hex가 아니라 역할을 나눈 것이다.**

| 토큰 | 값 | 역할 |
|---|---|---|
| `bg.brand-solid` | `#0266FB` | 버튼·핀 바탕 · **앱 아이콘**. 흰 글자 4.89:1 (**모든 글자 크기 통과**) |
| `bg.brand-solid-pressed` · `fg.brand` · `fg.brand-contrast` · `stroke.brand-solid` | `#0250C5` | 텍스트·아이콘·테두리. 흰 배경 7.10:1 (AAA) |
| `bg.brand-weak` | `#EEF5FF` | 약한 배경 |
| `bg.brand-weak-pressed` | `#E0ECFF` | 약한 배경 pressed |
| `stroke.brand-weak` | `#BBD6FE` | 약한 테두리 |

**앱 아이콘과 같은 값이다.** 파랑이 하나뿐이므로 로고 전용 상수를 따로 두지 않고, 어느 자리에 어느 파랑을 쓸지 판단할 일이 없다. 아이콘 원본 `#0D6EFD`를 그대로 토큰으로 쓰지 않은 이유는 **흰 글자 대비가 정확히 4.50:1로 여유가 0**이기 때문이다. 검사 도구의 소수점 처리나 색 프로파일 변환에 따라 4.49로 계산돼 감사에서 미달로 잡힐 수 있다. hue와 채도를 유지한 채 명도만 한 단 내렸고 원본과의 ΔE는 5.4다.

[주의] **아이콘 에셋 재출력이 남아 있다.** client 저장소의 `AppIcon.appiconset`·`web/icons`가 아직 Flutter 기본 로고다. 그것을 `#0266FB`로 다시 그려야 "아이콘과 같은 값"이라는 위 서술이 사실이 된다.

**지켜야 할 불변식은 hex가 아니라 기준이다.**

- `bg.brand-solid`는 **흰 글자 대비 4.5:1 아래로 내려가지 않는다.** 이 하한이 있어야 이 색 위 라벨에 크기 제약이 없다. `SeedActionButton` 기본 14px·`xsmall` 13px·`SeedBadge` solid 11~12px이 전부 WCAG 큰 글씨 기준(18.66px) 아래라 3:1 전제로는 못 쓴다.
- `fg.brand`는 **흰 배경 대비 7:1 이상**을 유지한다.
- **바탕과 글자를 한 값으로 합치지 않는다.** carrot 체계가 막혔던 원인이다.

적용은 `src/app/layout.tsx`의 `BRAND` 블록 하나로 한다. SEED에 팔레트 교체 API가 없어 CSS custom property 재정의가 유일한 경로다. **선택자는 `:root[data-seed][data-seed-color-mode="light-only"]`여야 한다.** SEED가 특정도 (0,2,0)으로 선언하므로 맨 `:root`(0,1,0)는 소스 순서와 무관하게 진다.

### 2. 17광역 tone과 4계열을 전면 교체한다

값 정본은 `src/design/bundle.tsx`의 `REGIONS`·`CATEGORY_GROUPS`이며, docs `03-디자인/디자인시스템.md`가 같은 값과 색별 근거를 문서로 보관한다.

**17광역은 `tone`·`dark`·`soft` 3역할이다.** 한 값이 실루엣 채우기와 흰 카드 위 % 글자와 표지 바탕을 겸하면, 글자 역할 때문에 흰색 대비 4.5:1이 강제되고 그건 L\* 50 이하를 뜻한다. 17색을 그 좁은 어두운 대역에 밀어넣느라 채도를 포기해야 했다. **브랜드가 탁했던 것과 정확히 같은 구조적 원인이고, 같은 방식으로 푼다.**

| 역할 | 쓰임 | 대비 요구 |
|---|---|---|
| `tone` | 실루엣 채우기 · 진행바 · 지도 폴리곤 | **없다** |
| `dark` | % 숫자 · 표지 글자 | 흰 배경 4.5:1, `soft` 위 4.5:1 |
| `soft` | 약한 배경 tint | - |

`tone`에 대비 하한을 두지 않는 근거는 **WCAG 1.4.11이 "내용을 이해하는 데 필요한" 그래픽에만 적용**된다는 것이다. 도감 채움률은 % 숫자와 지역명이 같은 정보를 따로 전달하므로 색이 유일한 전달자가 아니다. 하한을 걸면 노랑·연두가 밝을 때만 그 색으로 읽히는 탓에 광주가 올리브가 되고 "빛고을"이 남지 않는다.

결과 지표.

| 지표 | carrot 시절 | 현행 |
|---|---|---|
| 17광역 `tone` 상호 최소 ΔE | 11.8 | **23.5** |
| 지역색 대비 | 2.24:1 (흰 글자, 대구) | **`dark` 5.34:1** (역할 분리) |
| `soft` 위 `dark` 대비 | - | **4.71:1** |
| 4계열 흰 글자 대비 최저 | 3.33:1 | **4.56:1** |
| 브랜드와 가장 가까운 지역색 | ΔE 4 | **ΔE 30.2** |
| 4계열·칭호와 최소 ΔE | - | **23.6** |
| 내부 충돌 쌍 | 5 | **0** |

[주의] **브랜드의 최근접 이웃이 청록이 아니라 보라다.** `#0266FB`는 문화 계열 `#6541F2`와 ΔE 26.7이 최근접이다. 임계 22.5는 넘지만 도감 카드에서 브랜드 버튼과 문화 배지가 붙는 자리는 실화면으로 확인한다.

### 3. 칭호 5티어 색도 같이 고친다

흰 배경 위 글자로 쓰이는데 표고 `#FF9200`이 2.24:1로 미달이었고, 광역 `#0066FF`는 구 서울 tone과 같은 값이라 브랜드가 파랑이 된 뒤 브랜드와 혼동되는 자리였다. 전부 4.5:1 이상으로 바꾸고, **티어 색 텍스트에 `opacity`를 걸지 않는다.** 흰 배경에 합성되면 실효 대비가 2.30~3.30까지 떨어진다.

값과 검증은 docs `03-디자인/디자인시스템.md`의 "칭호 5티어 색" 절이 정본이다.

### 4. 자체 CSS 0개 규칙을 고친다

"자체 CSS 0개"를 **"SEED 토큰 재정의 1블록 외 자체 CSS 0개"**로 바꾼다. 새 `--*` 토큰 선언·`.css` 파일 추가는 계속 금지다. brand 축은 도입사가 갈아끼우라고 열어 둔 자리라 규칙 위반이 아니다.

## Consequences

쉬워지는 것.

- 도감 화면에서 지역 구분이 실제로 된다. 서울과 경기가 ΔE 11.8이던 상태가 해소됐다.
- 지역색·계열색·티어색 전부가 글자를 안전하게 얹는다. 17광역은 `dark`가 그 역할을 진다.
- **파랑이 하나다.** 브랜드색과 앱 아이콘이 같은 값이라 로고 전용 축을 두지 않는다.
- `bg.brand-solid` 위 라벨에 크기 하한이 없다. 허용 글자 크기 목록을 관리할 필요가 없다.

어려워지는 것과 리스크.

- **값이 세 곳에 손으로 복제된다.** docs `03-디자인/디자인시스템.md`, mockup `src/app/layout.tsx`, client `lib/design/tokens/brand_overrides.dart`. **어긋나도 기계가 잡지 못한다.** 실제로 2026-08-03 브랜드 교체가 mockup과 docs에 먼저 들어가 client가 하루 넘게 구 값으로 남았다.
- [중요] **17광역이 지금 갈라져 있다.** 여기 `REGIONS`는 3역할 값이고 client `catalog_reference_data.dart`는 **구 단일 `tone`**이다. 이식 여부를 담당자와 협의 중인 의도된 상태이나, 그동안 두 저장소의 도감 색이 다르다.
- 재정의가 특정도에 의존한다. SEED가 상위 버전에서 선택자를 바꾸면 조용히 깨진다. 업그레이드 때 브랜드색 렌더를 눈으로 확인해야 한다.
- 17광역이 두 차례 교체돼 기존 스크린샷·발표 자료의 색이 전부 달라진다.
- 지역 `tone`이 밝아지면서 지도에서 개별 지역의 인상이 부드러워졌다. 4계열 색이 상대적으로 강한 것은 의도한 결과다.

## Alternatives

| 대안 | 기각 사유 |
|---|---|
| carrot `#FF6600` 유지 | AA 미달 2.94:1과 충북 tone ΔE 4가 해소되지 않는다. 당근 오인 소지도 남는다 |
| 아이콘 원본 `#0D6EFD`를 그대로 토큰으로 | 흰 글자 대비가 **정확히 4.50:1**이라 여유가 0이다. 도구의 반올림이나 색 프로파일 변환에 따라 미달로 잡힌다 |
| 아이콘을 `#0B72C4`(구 브랜드값)로 다시 그린다 | 방향은 맞지만 아이콘이 탁해진다. 아이콘은 작게 표시돼 채도가 낮으면 스토어 목록에서 눈에 띄지 않는다 |
| 로고 전용 색을 따로 둔다 | 파랑이 둘로 늘고, 어느 자리에 무엇을 쓸지 매번 판단해야 한다. 2인 팀에서 규칙이 지켜지지 않는다 |
| `bg.brand-solid`를 `#0A84D8`로 (최초 확정값) | 흰 글자 3.96:1이 WCAG **큰 글씨** 기준 3:1 전제라 기본 크기 컴포넌트에서 깨진다. `SeedActionButton` 기본 14px·`SeedBadge` solid 11~12px이 전부 4.5:1 미달이 되어 carrot과 같은 AA 미달이 재현된다 |
| 깊은 파랑(딥 오션 `#0F4C81` 8.86:1 · 애저 `#036AA7` 5.80:1) | 지역색을 안 건드려도 되지만 여행 앱 톤에 비해 무겁다. 사용자가 두 차례 "너무 어둡다"고 판단했다 |
| 딥 틸 `#00857A` | 대비 4.53:1로 AA 턱걸이라 조정 여지가 없다. 역할 분리 이득도 없다 |
| 파랑대 6개만 옮기고 나머지 11개 유지 | 흰 글자 대비를 맞추려 명도를 낮추면 주황대 5개가 ΔE 0.4로 뭉친다. 수학적으로 성립하지 않는다 |
| 17광역 `tone`에도 흰 배경 3:1을 요구 | L\*가 60 아래로 묶여 노랑·연두가 죽는다. 광주가 올리브 `#A09100`이 되어 "빛고을"이 남지 않는다 |
| 17광역을 무채색·라벨로만 식별 | 도감 정체성이 색 매트릭스라 색을 버리면 제품이 바뀐다 |
| 밝은 하늘색(`#2EA8F0` 등)을 장식용으로 별도 도입 | 구 부산 `#00AEFF`와 ΔE 5, 구 인천 `#00BDDE`와 ΔE 4로 지역색과 겹쳤다. 재배치 전 기준 |

## 변경 이력

**이 문서는 결정이 바뀔 때마다 고쳐 쓴다.** 새 번호를 따지 않는 근거는 docs `협업규칙.md`의 ADR 절이다.

| 날짜 | 무엇이 왜 바뀌었나 |
|---|---|
| 2026-08-02 | 최초 확정. `bg.brand-solid` `#0B72C4` / `fg.brand` `#075C97`, 17광역 단일 `tone` 17개, 4계열, 칭호 5티어를 함께 재배치했다. 그날 안에 `#0A84D8`(3.96:1) → `#0B72C4`(4.98:1)로 한 단 낮췄다 - 최초값이 WCAG 큰 글씨 3:1 전제였는데 실제 컴포넌트에 18.66px 이상인 자리가 없었다 |
| 2026-08-03 | **브랜드 8개를 앱 아이콘 기준으로 재정렬.** `#0266FB` / `#0250C5`, weak 3개 동반 이동. hue 205도 → 216도. 아이콘과 브랜드가 다르면 파랑이 둘이 되고 "로고 전용 색" 축을 따로 관리해야 해서다. **역할 분리 구조는 그대로다.** client 저장소는 같은 결정을 client ADR-0009로 기록했다 |
| 2026-08-04 | **17광역 전면 재확정.** 값이 탁하고 지역 특성을 담고 있지 않다는 판단이며, **단일 `tone`에서 `tone`·`dark`·`soft` 3역할로 구조가 바뀌었다.** 색은 전부 그 지역에 실재하는 사물에서 가져왔다. 4계열과 칭호 5티어는 2026-08-02 값 그대로다 |
| 2026-08-07 | **본문을 현행 값으로 고쳐 썼다.** 그전까지 이 문서는 Decision에 구 값(`#0B72C4`·단일 `tone`)을 담은 채 맨 위 "값 정정" 블록으로 차이를 설명하고 있었고, Status에 `(대체 ADR 미작성)`, 본문에 "정식으로 supersede할 새 ADR 작성이 남아 있다"고 적고 있었다. **같은 날 세 저장소가 "번복되면 고쳐 쓴다"로 통일돼 그 대체 ADR은 애초에 쓰지 않는 것이 됐다** |

> **2026-08-03·08-04 개정의 `Author`가 기록돼 있지 않다.** 원 문서가 정정 블록에만 남겨 두어 누가 판단했는지 추적할 수 없다. 앞으로 이 표에 개정자를 함께 적는다.
